# Regole di lavoro

- Non lavorare direttamente su `main`: usa un branch dedicato e una pull request.
- Un ticket per branch.
- Non modificare moduli non correlati al ticket.
- Frontend e backend devono rispettare i contratti API condivisi in `docs/api-contract.md`.
- Esegui i test pertinenti dopo modifiche significative; segnala se non esistono ancora test eseguibili.
- Niente merge con test falliti.
- Preferisci semplicita e dipendenze minime.

L'architettura applicativa sara definita successivamente con `/grill-with-docs`.
